# Roadmap v2 — The Rebuild Onward

Status: ACTIVE — the plan of record after the folders substrate.
Date: 2026-07-18

Dependency-ordered, never time-estimated. Each phase runs the same loop that
built Phase S, M1/M2, and the folders substrate: **design conversation (where
taste matters) → spec → implementation plan → reviewed subagent build →
live verification against real libraries**. A phase is done when it is
personally usable (ADR-0007), gated green (typecheck · lint · unit ·
integration), and its decisions are recorded so no future session relitigates
them.

## Phase 1 · Track A part 2 — The Frame

**Goal:** the mastermind window — organization and navigation become the way
the app is entered. Everything renders over existing, tested APIs; zero new
business logic.

Implementation phases:

- **F0 — Design session** (gate: Ahmed's taste, per O·B·L·A Track A). Layout
  of the three-pane spine; density; filing ergonomics; what ⌘K matches;
  keyboard map. Produces the frame spec.
- **F1 — The spine layout.** Sidebar (All · Uncategorized · folder tree ·
  Smart Folders placeholder · tags · libraries) + river scoped by rail
  selection + detail/hub panel. Read-only; selection is real state, no
  overlays.
- **F2 — Filing gestures.** Multi-select in the river; one-keystroke
  add/remove to folder; new/rename/move/delete folder in the rail (surfacing
  FolderError codes as friendly messages — deferred item from part 1);
  "Import from Eagle" gesture wired to D-A6.
- **F3 — ⌘K switcher.** Jump to folder / document / library by typing;
  history back/forward stack (⌘[ / ⌘]) over selection state.
- **F4 — Polish pass + deferred minors.** Rail ghost-count variant decision,
  boot-mirror timing if first paint needs it, appearance polish.

Exit: the seeded tree navigable; filing cheaper than in Eagle; Uncategorized
inbox drives real filing of the ~800 unfiled documents.

## Phase 2 · M3 — Reader + Reading Ledger

**Goal:** read inside the mastermind window and never keep a second scrapbook
— per-page coverage over books explored nonlinearly.

Implementation phases:

- **R0 — Ledger spec freeze** (shape already in spine spec v2 §3; freeze the
  event vocabulary + rollup contracts).
- **R1 — `astro://` + Reader core.** pdf.js quarried (asset packs return to
  the vite config), continuous-scroll reader inside the frame's detail pane.
- **R2 — The ledger.** Append-only per-page session events (view · zoom ·
  select · find-hit), hash-keyed files; derived rollups: page → TOC section →
  document coverage, unread frontier, staleness.
- **R3 — Assertions.** The D1 flags (*read / skimmed / revisit / key*) per
  page/section + document `finished`; observed vs asserted kept rigorously
  separate (engagement, never comprehension).
- **R4 — Canvas.** Whole-book heat overview (breadth/depth quarried),
  page-range Views return.

Exit: open a book from the river, read, close, reopen — coverage and
frontier persist; the Canvas shows where you've been.

## Phase 4 · M5 — The Agent Returns

**Goal:** converse with the library on your own accounts, inside the frame.

- **A1 —** MCP server over the index (quarry; esbuild bundle; asar-unpack
  set returns).
- **A2 —** ACP client: adapters (Claude/Codex), update-map, permission
  policy, dialogue store (quarry largely whole — the newest v1 code).
- **A3 —** Dialogue pane in the frame; safe-reads allowlist; resumable
  chats.

Exit: the agent can search, browse, and cite the unified library; every
token spent deliberately (zero-token navigation stays the rule).

## Phase 6 · Track B — The Graph (the founding "mind")

**Goal:** the knowledge layer the rebuild's spine was designed to carry.

- **B1 —** embeddings + semantic search (sqlite-vec; verify extension load
  under Electron ABI FIRST — the known risk; fallback brute-force cosine).
  BYOK key storage via safeStorage (first stored key; design once).
- **B2 —** graphify substrate: origin-tagged edges over documents/notes
  (wiki-links + folders + annotations as first edge sources).
- **B3 —** graph lens + curation in the frame.
- **B4 —** Orion (in-app extraction) stays PARKED until graphify stops
  sufficing — by design.

Exit: "what connects these" answerable zero-token; Alioth's justification
(bespoke graph context assembly) now exists.

## Phase 7 · Track O — OCR *(can interleave with B; feeds B1 text for scans)*

  once O1 quality on real scans is known.
- **O4 —** durable hash-keyed cache (survives wipeDerived by design) +
  in-view OCR text.

## Standing rules (carried from the rebuild, non-negotiable)

- Dependencies arrive with their first consumer; pnpm settled.
- Spec leads code; spec wins over plan on conflict; TDD ∝ stakes × logic,
  mutation-checked at load-bearing rules.
- Owns no content: user-authored data (folders, reading ledgers, marks) is
  files-as-truth; SQLite is always disposable.
- Every phase ends usable, or it isn't a phase end.
